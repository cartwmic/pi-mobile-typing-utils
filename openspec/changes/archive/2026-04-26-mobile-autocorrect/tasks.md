## 5. AutocorrectEditor Component

- [x] 5.1 Create `src/autocorrect-editor.ts` with `AutocorrectEditor extends CustomEditor` — constructor accepts `tui`, `theme`, `keybindings`, a `CorrectionEngine`, a `LearnedDictionary` instance, and a `UIAdapter` interface (`{ setStatus(key: string, value?: string): void; notify(message: string, level?: string): void }`). Status clearing uses `setStatus(key, undefined)` — no separate `clearStatus` method needed. The editor SHALL NOT reference `ctx.ui` directly.
- [x] 5.2 Implement token extraction: on space/punctuation trigger (`. , ; : ! ?`), extract the token before the cursor using `getText()` and `getCursor()`. The canonical eligibility rule is: **token must match `^[A-Za-z]{3,}$`** (pure ASCII alphabetic, 3+ chars, no other characters — this implicitly rejects paths, dots, underscores, all hyphens, digits, apostrophes, and non-ASCII). When checking word boundaries, verify BOTH the character before the trigger (must be a letter) AND the character after the insertion point (must be absent, whitespace, or punctuation — to avoid mid-word correction).
- [x] 5.3 Implement word replacement using cursor-aware operations (programmatic backspace to delete the original word, then insert the correction + trigger character) to avoid whole-buffer `setText()`, keep cursor state correct, and preserve the immediate-backspace undo path. Task 4.7 verified that Pi's public editor API does **not** expose an atomic delete+insert undo-batching primitive, so built-in undo parity for accepted corrections is best-effort only. For multi-character `handleInput(data)` payloads (paste, SSH buffer): if the payload starts with `\x1b`, pass the entire payload through to `super.handleInput(data)` (escape sequence — task 4.7 static analysis found that Pi normally delivers complete escape sequences separately from trailing printable text, with bracketed paste as the important ESC-prefixed whole-payload case). Otherwise, process byte-by-byte: known single-byte control characters (backspace `0x7F`/`0x08` → undo-check handler; Enter/Tab → delegate to super) are dispatched individually; printable text accumulates and triggers correction at each trigger character position. **Before/after delegating any control character or escape sequence to super, set `lastCorrection.committed = true`** (non-printable events commit any pending correction). When multiple corrections occur in a single payload, the status line shows the last correction only (previous timer cancelled).
- [x] 5.4 Implement backspace-to-undo: track last correction state (`{ original, position, committed: false }`), on backspace when not committed restore original word via cursor-aware operations and call `learnedDictionary.recordRejection(original)`; on any other key set `committed = true`. After a rejection, add the original word to a `recentlyRejected` map keyed on `(lineIndex, wordStartOffset)`. Cap the map at 32 entries with FIFO eviction to prevent unbounded growth in long sessions. The suppression prevents the same correction from re-triggering at that position. Clear the entry when: (a) the cursor leaves the line, (b) the cached offset no longer points at the original word string (due to edits shifting positions), or (c) the word is deleted entirely. Re-validate at trigger time (see spec). Note: in multi-correction payloads, only the LAST correction can be undone (previous corrections' `lastCorrection` state is overwritten) — documented as known limitation.
- [x] 5.5 Implement `isShowingAutocomplete()` guard — skip correction logic when autocomplete dropdown is visible
- [x] 5.6 Implement correction feedback via status line: on correction, **cancel any previously scheduled clear timer**, then call `uiAdapter.setStatus("typos-correction", "✓ teh → the")` and schedule a new 500ms timer to clear it via `uiAdapter.setStatus("typos-correction", undefined)`. Clear immediately on next input. This ensures back-to-back corrections don't race (the second correction's timer replaces the first's). All UI calls go through the injected `UIAdapter`, not `ctx.ui`.
- [x] 5.7 Integrate rejection notification — when `recordRejection` returns `{ learned: true }`, show `uiAdapter.notify("Learned: <word>", "info")`. All UI calls go through the injected `UIAdapter`.
- [x] 5.8 Write automated unit tests for AutocorrectEditor: mock CustomEditor parent and UIAdapter, test space-trigger correction, punctuation-trigger, backspace-undo (including: tracking cleared after undo, cursor movement commits, double-backspace = undo then normal delete), commit-on-other-key, autocomplete-guard, short-word-skip, non-alphabetic-token-skip (including apostrophe `don't` and non-ASCII `café`), cursor-not-at-word-boundary skip (including mid-line insertion), double-space skip, re-correction suppression after rejection (including edge cases: edits before rejected word, cursor leaves line, word deleted), multi-character paste input handling (including interleaved control characters and multi-line paste), escape sequence passthrough (arrow keys, etc.), multiple corrections in single paste (verify status shows last only), toggle serialization races (off-during-on-load, double-on-load, no-args-during-load — assert final-state-wins and single engine init)
